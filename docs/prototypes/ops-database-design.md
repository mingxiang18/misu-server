# 运维中心「数据库」UI 原型设计说明

状态：2026-09-13 用户已回复“没问题，按这版开发吧”，本原型进入实现依据；页面最终接入 misu-ops 原生数据库 API，不接入第三方数据库管理 UI。

原型文件：[`ops-database.html`](./ops-database.html)

## 设计定位

这是运维中心中「数据库」标签的桌面优先静态原型。界面延续 misu 现有的温暖浅色底、焦糖橙色主色、克制阴影、8–12px 圆角和 Element Plus 风格的表单控件。内容以表数据为主，给表格留下连续的横向空间；在 800px 以下切为上下布局，保留数据库、表搜索和主要操作。

页面顶部保留 Nacos 控制台、Kubernetes、SSH 终端、下载任务、数据库五个运维标签，并将数据库标记为当前页。页头角标「UI 原型 · 模拟数据」说明当前文件仍是静态演示；最终页面通过 `/ops/api/database/**` 获取数据，不提供任意 SQL 编辑器或危险批量操作。

## 已覆盖的交互

- 数据库下拉选择（`misu` / `misu_test` 的展示占位）。
- 侧栏表列表、表名搜索、行数、无主键的「只读」提示。
- 「数据」和「表结构」标签切换。
- 数据表分页（每页 5 行）、任意字段文本筛选、订单状态筛选、点击字段名排序。
- 有主键表支持新增行、编辑行、按主键删除确认；无主键的 `activity_logs` 只读。
- 新增/编辑抽屉为每个字段展示必填、允许空值、默认值和自增说明。
- 「新建表」对话框会模拟创建带 `id`、`created_at` 字段的示例表；「添加字段」对话框会将字段追加到当前表并给既有行填充空值。
- 所有操作只更新 JavaScript 内存；「刷新」会恢复初始模拟数据，浏览器刷新也会复原。操作结果用轻量提示反馈。

## 最终接入边界

- 数据库页面只面向 ADMIN，使用目标专属 `/ops/database/` 会话；Secret、连接 URL、密码和 SQL 不进入浏览器。
- 表列表、metadata、分页/排序/筛选、单行增删改、新建表和添加字段由 misu-ops API 提供；服务端固定 schema、字段和类型 allowlist，并对值使用参数化 SQL。
- 只有单列主键表可写；无主键和复合主键表只读。新建表/添加字段是受限 DDL，不开放任意 SQL、账号授权、批量危险操作或整库备份恢复。

## 数据和边界

示例数据只有假名字、订单、账号、文件分享和操作日志。原型刻意不提供 SQL 编辑器、批量删除、批量导入导出、索引/权限/事务等复杂管理入口；事务、并发、审计和错误码由后端 API 负责，UI 只呈现安全结果。

建议审核时重点关注：表侧栏是否足够快速、数据区的可读宽度、无主键只读边界、删除确认是否清楚，以及新增/编辑抽屉中空值与默认值提示是否足以降低误操作。
